# kains2866/vault-change-feed

Records every create, modify, delete and rename in the vault as a machine-readable event stream with line-level diff counts, so a program can read what changed instead of rescanning every note. Each reader keeps its own cursor and receives only newer events, with repeated edits to one file collapsed into a single cumulative line; on startup the plugin reconciles against a baseline snapshot to backfill changes made while Obsidian was closed, using content hashes to spot renames. Data stays under the plugin folder in a JSONL event log, a cursors file and a compressed baseline; the log is capped by age and entry count, and readers are told when a full rescan is needed. A reading-protocol block is installed into agent instruction files on first run, and concurrent instances coordinate through a heartbeat lock so only one instance records.
