# anseyuyin/line-ending-controller

Line Ending Controller is described as controlling line ending format per file or per folder and preventing Obsidian from silently converting CRLF to LF. The README explains the cause: Obsidian's CodeMirror editor normalizes line endings to LF internally, so saving a CRLF file rewrites it even without edits, which the README connects to unexpected Git diffs, linting failures and mixed endings in a team. The plugin corrects endings after every save and, by default, on open, following per-file or per-folder rules matched by longest path prefix with an empty pattern as the fallback, and it shows the active file's ending in the status bar alongside manual conversion commands. Its interface follows Obsidian's display language in English or simplified Chinese.
