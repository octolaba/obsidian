# emilbob/obsidian-automation-graph

Automation Graph draws a repository's automation as a graph built from the workflow files themselves, re-read every time the view opens rather than maintained by hand. It parses GitHub Actions workflows for their schedules and triggers and for what their steps do, optionally reads Claude Code hooks and agents, and infers edges where two files agree, such as one workflow producing a branch another waits on. Automation that runs outside the repository can be declared in a nominated vault note and is drawn as dashed nodes labelled as unverifiable, while a workflow that no note describes is reported as drift. The repository is found by a bounded scan beside the vault and under the home folder, or set by path in settings, and an optional GitHub connection colors only failing, running or stale nodes, leaving anything it could not fetch unmarked.
