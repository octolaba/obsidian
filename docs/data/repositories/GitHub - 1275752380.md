# Wjiajie/obsidian-aliyun-sync

Obsidian plugin that keeps a vault in sync with a folder in personal Aliyun Drive through the service's open file APIs, so neither the desktop client nor a locally mirrored folder is required. Authorisation uses an OpenList refresh-token flow, and the token is stored only in local plugin data, never uploaded to the sync folder and never written into logs. Synchronisation is two-way and incremental, planned from local state, remote state, sync history and SHA-1 content hashes, and it runs at startup, on an interval and after a delay following file changes, with configurable parallel transfers, retries on transient or rate-limit failures, and status-bar progress. Markdown conflicts leave unresolved copies in the plugin metadata folder, and there are guards against large-scale deletion propagation and against auto-renamed duplicate folders.
