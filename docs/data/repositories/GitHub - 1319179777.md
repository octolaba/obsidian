# Yuriyagn/controlled-tagger

Controlled Tagger asks an OpenAI-compatible model to suggest tags for the active note but restricts it to a registry the user maintains: returned tags are intersected with that allow-list locally, shown as a multi-select, and written only after confirmation, either appended or replacing the frontmatter tags. The registry can be seeded from tags already in the vault, extended by hand or by import, and renamed or deleted across matching notes, with the number of affected notes shown before a vault-wide change. A tag semantic library derives each tag's meaning and boundaries from existing notes, refreshed manually or on an opt-in schedule. Requests go directly to the configured endpoint, the API key and generated summaries live in the plugin's local data file, and there is no telemetry.
