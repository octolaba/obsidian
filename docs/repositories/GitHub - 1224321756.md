# MMoMM-org/miyo-tomo-hashi

MiYo Tomo Hashi bridges Obsidian to MiYo Tomo, a separate Docker-hosted project that the README says the plugin cannot really be used without. It combines three components that share only the plugin process and the settings tab: a chat tab attached to a running Tomo container, an opt-in loopback WebSocket that reports the active file, cursor position and selection, and an executor that applies the batch vault edits described in the `_instructions.json` files Tomo emits. The README records that nothing in the vault changes before the action list has been previewed, even in auto-run mode, and that every action carries an idempotency probe and is marked as applied so a re-trigger resumes after a crash or a partial cancellation; the executor itself is described as pure code with no AI component.
